# Guiyuan Vibecoding 产品基线 v0.1.0

> 状态：当前产品基线摘要；详细能力验收见同目录各 capability 文档
> 生效日期：2026-09-02
> 版本：0.1.0

## 1. 定位

Guiyuan Vibecoding 是独立封装的低 Token 软件项目管理与迭代治理产品。用户通过 Agent、
Skill 或本地管理界面描述目标，VCM 负责建立项目事实、规划工作、验证交付并维持可追溯状态。

VCM 不依赖 Private Butler。安装 PB 后可以获得跨场景候选任务和用户偏好，但项目仍由 VCM
及其仓库独立管理。

## 2. v0.1.0 核心能力

- 新项目初始化、现有项目只读评估及可选择的治理接管。
- 低 Token 的单项目与多项目方法论：NOW 优先、字段/片段检索、增量续传和硬预算门槛。
- 产品、功能、技术栈、拓扑、任务、进度、验证、变更台账和归档的权威工件。
- 单项目详情与多项目总览管理界面；界面读取仓库事实，不另造项目真相。
- 确定性结构、漂移、版本和交付检查。
- Agent/Skill 驱动的完整工作流；没有 PB 或云服务时仍能独立工作。
- 管理界面设置页：用户可查看并调整 VCM 的 Provider、迁移确认等本地设置。
- 脚手架保留完整目录契约：空的 `docs` 分层、`apps`、`workers` 也必须以占位文件保留。
- 现有项目采用渐进接入：只读检测新旧目录/权威文档冲突，经用户确认后分步迁移。

## 3. 数据与产品边界

- 每个项目仓库是该项目代码、需求、决策、状态和交付证据的唯一权威。
- VCM 保存项目治理信息，不保存个人生活记忆，也不接管 Creator OS 的创作语料和资产。
- 多项目总览保存索引和派生摘要，不把多个仓库复制成新的中心权威库。
- PB、Creator OS 和第三方服务只能作为可选输入、执行器或输出目标。

## 4. 可选 PB 集成

VCM 可声明项目分析、代码实现、测试、文档和发布等能力，并接收 PB 或第三方路由器提交的
任务候选。候选至少包含 `dispatch_id`、`idempotency_key`、来源引用、意图、优先级、风险、
摘要和授权状态。

嵌入/向量全部由 PB 承载（bge-m3 + 向量库）；VCM 通过 `pb_enabled` 开关决定是否接入 PB，接入后
只经稳定接口做语义评分与上下文读取，自身不持有模型或向量库，也不复制项目规格进个人记忆。
独立 VCM（`pb_enabled=off`）保持零模型、零向量：确定性检索 + LLM provider。

收到候选不等于开始执行。默认流程：

```text
candidate -> inbox -> user review -> accepted/rejected
          -> planned -> executed -> verified -> result receipt
```

VCM 返回结构化执行状态、摘要、错误原因、权威仓库产物引用、验证证据和来源关联。PB 可以保存
个人相关摘要和指针，但不得成为项目事实的权威副本。

- PB 不可用：VCM 的本地工作流不受影响。
- 候选重复：以幂等键复用原任务或原结果，不重复执行。
- 用户拒绝：记录拒绝，不修改项目。
- 执行失败：保留失败证据，按 VCM 自身状态机决定修复或阻塞。

## 5. 产品化

- 免费：用户自己的 Agent、本地 Skill 和本地项目治理，可选连接本地 PB。
- 成本模式：用户自带模型/API，托管方只收取明确的基础设施或增值服务成本。
- 收费：官方 API、云端多项目管理、托管执行和高级治理能力。
- 各模式遵循同一权威边界；付费与否不改变用户项目数据的所有权。

## 6. v0.1.0 验收

- 不安装 PB 和 Creator OS 时，可完成项目初始化、规划、实施、验证和归档闭环。
- 多项目总览能链接回各仓库权威事实，且不制造冲突副本。
- 可选 inbox 必须经过用户确认，并能处理重复、拒绝、失败和结果回传。
- 正常管理上下文保持在既有 Token 预算门槛内。
