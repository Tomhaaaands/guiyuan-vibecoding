# Project Home 生成蓝图（可复用）

> Status: accepted design (2026-09-04). 目标：同一套框架（TITLEBAR / HOOK / BODY-TAB / FOOTER）
> 能为任意被接管项目自动生成单文件项目主页 `*-home.html`；框架不变，只替换一个 `PROJECT` 数据块。
> 本页是**只读派生视图**：不修改业务代码，所有事实来自项目内权威文件，链接一律用相对路径（项目文件夹移动后不失效）。

## 1. 固定骨架（不随项目变化）

```text
TITLEBAR  首页 / 快速开始 / 项目详情 / 关于归园 / 大管家 / GitHub（毛玻璃、吸顶）
HOOK      banner（项目身份 + 运行状态 + 陶渊明融合底图） + 三步快速开始（默认折叠）
BODY      4 个 TAB：系统架构图 / 项目进度 / Roadmap / 文档总览
FOOTER    归园代码原理介绍（闭环卡片） / 归园大管家 / 卸载攻略
```

换项目时骨架、样式、交互（TAB、左右 master-detail、移动端底部弹层、目录树、一键复制、空状态）全部复用。

## 2. PROJECT 数据块与派生来源

| 字段 | 派生来源（按优先级） | 兜底 / 空值规则 |
| --- | --- | --- |
| `identity.title` | README 一级标题 / package 名等**项目内明确声明名** | 项目文件夹名；都没有显示 `--` |
| `identity.version` | 项目 `VERSION` / package 版本 | `--`（不是归园工具版本） |
| `identity.iter` | `NOW.md` 日期 + CHANGELOG 最新轮次 | `--` |
| `identity.address` | 项目根，固定用相对路径 `./` | —— |
| `installed` | 探测 `.guiyuan-vibecoding/`、`.codex/hooks.json`(vcm)、技能目录等标记 | 无标记→`false`，快速开始标「未安装」且默认展开 |
| `archLayers[]` | 系统架构文档（如 `00-system/manager-architecture.md` 四平面）+ 真实代码目录；每层含模块，模块含职责 / 步骤 / 文档链接 | 空数组→架构 TAB 显示「暂未检测到项目」 |
| `modules[]` | 产品能力索引（`01-product/*/prd.md`+`acceptance.md`）× 技术责任域 × CHANGELOG 最近轮次；字段：阶段 / 完成度 / 最近改动 / 改动介绍 / 阻塞点 / 文档 | 空数组→进度 TAB 空状态 |
| `roadmap[]` | `01-product/roadmap.md` + 归档轮次；**按时间从近到远**排序，带状态与完成度评估、验收句、归档链接 | 空数组→Roadmap TAB 空状态 |
| `principleFlow[]` | 产品真实实现链路（进入→认知→规划→执行→沉淀→复用→回流）；特色机制写进卡片要点 | 空数组→空状态 |
| `docTree` | 递归扫描项目文档 / 实现文件得到的嵌套树（目录 + 文件相对路径） | 空树→文档 TAB 空状态 |

### 2.1 架构分层归位规则（以 VCM 为例，其他项目类推）

- 先识别「入口/通道 → 认知/事实源 → 规划 → 执行验证 → 沉淀」主链；沉淀回写认知层形成闭环。
- **可插拔外部能力（如 PB 桥 / 第三方 API / 向量服务）是某层的 provider 缝，归入使用它的层，不单独剥成一层**。
  VCM 的 PB 桥服务于语义检索与用户上下文，归入「认知层 Project Brain」。
- 横切且不属于任何业务层的运行时约束（语言、仓库、缓存、确定性原则）放底部「基座」条。

## 3. 链接与路径契约

- 全部使用**相对路径**（`docs/...`、`tools/...`、`./`），禁止写死 `file:///` 绝对路径或盘符。
- 只链接真实存在的文件；发布模板 / 内部仓库双副本中的文件，链接到确实存在的那份。
- 生成后必须做一次「链接存在性校验」：逐个 `Test-Path` / `os.path.exists`，零死链才交付。

## 4. 空状态与缺字段（新项目 / 空文件夹）

- 任何 BODY TAB 的数据源为空：渲染 `.empty` 空状态「暂未检测到项目」+ 一句初始化引导。
- 任意标量字段缺失：统一 `dash()` 输出 `--`，不显示 `undefined`、不编造默认值。
- 新项目脚手架阶段：`archLayers/modules/roadmap/docTree` 都可能为空，属正常，初始化首轮后由生成器重新派生。

## 5. 生成步骤（供 render 工具自动化）

1. **身份**：读 README / VERSION / NOW / CHANGELOG / `git remote -v`，解析标题（声明名优先、文件夹兜底）、版本、最新轮次、远端地址、安装标记。
2. **架构**：读系统架构文档 + 扫描代码目录，产出分层与模块；为每个模块关联其产品 / 技术 / 实现文件。
3. **进度**：读能力 PRD/验收 + roadmap + CHANGELOG，按模块聚合最近轮次、状态、阻塞、完成度。
4. **Roadmap**：解析里程碑表，按最近时间倒序，补完成度与归档链接。
5. **文档树**：递归扫描（排除 `.git/dist/.preview/__pycache__` 等），归档按轮次号数字排序，输出嵌套 JSON。
6. **原理链路**：用该项目真实产品循环填充固定闭环骨架，把差异化机制写进卡片要点。
7. **装配**：把以上结果写入唯一 `PROJECT` 数据块，套用固定骨架模板输出单文件 HTML。
8. **校验**：链接存在性、标签平衡、桌面 + 移动渲染自检；通过后交付。

脚手架完成时首次执行渲染；`tools/rollup_round.py` 在写入每轮归档与 changelog 后自动再次
执行渲染。因此 `status.html` 随迭代边界更新，但始终只是可删除的派生文件。输出会内嵌
CSS 与装饰图片，浏览器可直接打开，不启动 8010 或其他本地监听服务。模板文件本身也可直开：
安装载荷在 `templates/assets/` 保留模板旁的装饰图副本，避免相对路径失效。

## 6. 交互契约（框架自带，复用即可）

- 架构：桌面端左图右详情（sticky）；≤860px 改为点击模块从底部弹出 sheet + 遮罩，可关闭。
- 文档树：原生 `<details>` 折叠，默认展开前两层、归档默认收起，提供全展开 / 全收起。
- 快速开始：`<details>` 默认收起；已安装打「● 已安装」标签。
- 一键复制：`navigator.clipboard` + `execCommand` 兜底，适配 `file://` 打开。
- 响应式：多列一律 flex-wrap；触控目标 ≥44px；移动端单列 / 底部弹层。

## 7. v5 增量（2026-09-04，换项目时同样复用）

- **Banner 全幅出血**：`.hero` 作为 body 直接子元素移出内容容器，左右贴边、顶部贴页面边缘（无圆角 / 无描边卡片感），内部再用一个与内容区等宽（1080）的 `.hero-inner` 约束文字；上内边距 ≥ 吸顶导航高度，保证内容不被 topbar 遮挡；人物图右贴 + 左缘渐变消失。
- **文档树每个节点都要带「干什么用」**：目录节点用保留键 `__d__`、文件节点用 `d` 存放一句中文说明；渲染时目录说明跟在计数后（灰色小字），文件说明另起一行缩进对齐。遍历 / 计数时把所有 `__` 前缀键视为元数据跳过。说明来源优先级：①curated 权威映射（根文件、系统/产品/技术文档）②规则生成（`prd/acceptance` 按能力名、`archive/*-rN.md` 按轮次号）③代码文件取模块 docstring（**仅当 docstring 含中文才直接用，否则走 curated 兜底**，避免把英文实现注释暴露给小白）。
- **原理卡 card-to-card 双层表达**：`principleFlow[]` 每卡含 `plain`（卡面大白话，默认可见）+ `t`（正式步骤名）+ `pts`（技术实现，藏在 `<details>` 点击展开体）；卡间用 → 连接（桌面横向、≤720px 旋转为 ↓ 纵向），末尾保留回流闭环条。原则：小白先读大白话链路，需要时再点开技术细节。
