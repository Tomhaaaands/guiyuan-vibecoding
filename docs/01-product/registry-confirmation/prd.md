# Registry and confirmation anchors · PRD

## Problem

Changing a project's code folders must not erase the manager's understanding of product scope,
technical work or the user's last decision.

## Outcome

Every managed project has a derived index of its human product/technical documents and four
explicit user gates: requirements (`REQ`), plan (`PLAN`), quality assurance (`QA`) and release
(`RELEASE`).

## Scope

- index module PRDs, acceptance documents, technical specifications and workflow artifacts;
- preserve the physical paths through the project manifest;
- keep user confirmation evidence immutable and hash-linked.

## Non-goals

The registry is not a replacement project database, and anchors do not auto-approve work or edit
human documents.
