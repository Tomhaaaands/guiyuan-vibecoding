当前痛点（按阶段）

  • 获取安装：要求 Python ≥3.11 与命令行操作，零基础用户有门槛
  • 进入会话：每个项目都要手动新开会话 + 显式调用，无跨会话常驻管家
  • 状态识别：指纹规则有限（manifest/package.json/pyproject/单脚本），冷门类型可能识别不准
  • 环境披露：三选一选项对小白略重，但"先披露后安装"是安全底线
  • 执行输出：仍偏"管理机制"细节，用户需要看 CLI/预检信息
  • 日常迭代：纪律靠 skill 引导 + pre-commit 门禁，无自动执行收据/状态推进；新会话恢复依赖 agent 读文件
  • 长期维护：版本/副本同步是维护者职责（已脚本化 sync_copies + check_drift）

与 vNext 契约的差距（未发布）

  • 无跨会话状态机（INTAKE→ANALYSIS→…→NEXT）与四平面架构
  • 无运行时上下文编译器（L0/L1/L2 切片、delta 续传、1,800 token 目标）
  • 无自动执行收据、任务依赖图与行为评估 harness（P2/P8）
  • "四句人话"尚未完全达成：预检选项、CLI 输出、changelog 行仍暴露给用户
  • 多客户端 / 工具调用标准（MCP）留待 P8 打包决策
