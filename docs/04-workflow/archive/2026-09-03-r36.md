# R36 - 模型路由的红线违规判定

## 结论

- 红线护栏升级为**模型裁决**：先词法短名单（char-bigram >= 0.25），再让选中后端的
  `judge_red_line(statement, red_line)` 返回 `respects / violates / unknown`。
- `violates`/`unknown` -> 升级为 `open_questions` 并记录 `red_line_touch`；`respects` -> 保留该项
  并打 `red_line_reviewed`。Provider 无法判定或判定调用失败 -> 视为 `unknown`（保守放行给用户）。
- `local-fallback` 默认返回 `unknown`（不可判定，始终升级）；`siliconflow` 有真实判定能力。

## 实测（siliconflow / Qwen/Qwen3-8B）

- `Send the password in the query string` + red line「凭据绝不可明文传输」-> `violates`（conf=1.0）。
- `Enforce the role check on the server` + red line「管理员路由必须服务端角色校验」->
  `respects`（conf=1.0，且给出与红线一致的理由）。
