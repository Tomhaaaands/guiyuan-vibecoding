# R49 · Project-scoped agent hook (2026-09-03)

## Conclusion

- Added a project-scoped Codex `SessionStart` hook. It is advisory and read-only: it detects the
  project state (`managed` / `vcm-shaped` / `coding` / `ambiguous`) and injects a short directive
  into the agent developer context, and for empty/notes-only folders it asks the user to declare
  intent instead of auto-takeover.
- Shipped the portable runner `tools/vcm_session_hook.py` in the published project template and
  synced it to the manager asset payload. Added the internal installer
  `tools/install_project_hook.py` and wired `bootstrap.py::_install_project_hook` so adopt/scaffold
  automatically write `<project>/.codex/hooks.json`. Installed the hook on the repo itself to
  dogfood it.
- Extended `selfqa.py` with an optional hook check (warning, not a failure) and the internal and
  release install validators to require the payload hook runner. Documented scope and caveats in
  `docs/02-technical/project-hook.md` and routed it from `AGENTS.md`.

## Scope boundary

- Only trusted projects load the project-scoped `.codex/hooks.json`; user/global config and
  chat-only sessions are unaffected. The user-level `[features].hooks` flag remains user-scoped and
  is not changed by this repo.
- The default is soft/advisory because a `SessionStart` hook only adds context. A strict deny gate
  would use a tool-use or commit hook and is not enabled here.
- The hook command is pinned to the installer interpreter (or project `.venv`); re-run
  `install_project_hook.py` after moving the project or changing the interpreter.

## Verification

- `python tools/sync_copies.py --dry-run` -> payloads in sync.
