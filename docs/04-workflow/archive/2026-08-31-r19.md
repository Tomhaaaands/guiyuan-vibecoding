# R19 · install-by-message distribution (Quark-style zip)（2026-08-31）

> Full iteration record. Not read during normal work; current facts live in NOW and the authority
> contracts.

## Goal

Lower the install friction. Today the kit installs via `install.bat` / `install.sh` or
`$vibe-coding-install`; the user wants a Quark-cloud-drive-style primary path: paste one message
with a 技能地址 zip URL and the agent installs it.

## Decisions

- **Primary install becomes install-by-message**: one self-contained zip
  `vibecoding-manager-<version>.zip`, zip root = exactly the three skill directories
  (`iteration-close-loop/`, `vibe-coding-manager/`, `vibe-coding-install/`), so unzipping into an
  agent's global skills directory installs the kit. No wrapper dir, no account authorization.
- The install message keeps the same phrasing as the Quark convention ("请安装 X Skill /
  技能地址：<zip url>"), minus the "并授权账号" clause.
- Update = resend the message with the newer zip URL (idempotent overwrite). The secondary
  `install.bat` / `$vibe-coding-install` path is kept for repo/Codex installs.
- The convention is codified in `skills/vibe-coding-install/SKILL.md` so any agent that unpacks the
  zip knows the five install steps (download → extract → copy 3 dirs to global skills → verify →
  report) and the update rule.

## Implementation

- Added `tools/build_dist.py`: reads root `VERSION`, packs the three self-contained skills into
  `dist/vibecoding-manager-<version>.zip` (excludes `__pycache__`/`.pyc`/`.git`), prints size +
  sha256, and `--verify` extracts to temp and validates installability (SKILL.md + openai.yaml per
  skill, bundled VERSION matches, zip root contains exactly the 3 skill dirs).
- Rewrote `skills/vibe-coding-install/SKILL.md` to make install-by-message the documented primary
  flow and relegate the repo/Codex installer to secondary.
- Updated README Quick start (three-part: install by message → install from repo → use) and the
  tool table / tool count (Ten deterministic tools).

## Verification

  sha256 `efbfa091…57c8`; temp-extract check green for all three skills, bundled VERSION 1.2.0,
  exact zip-root contents.
- `tools/check_drift.py` passed after the SKILL.md / README changes (markers, links, sync pairs,
  version gate).
- Full install-by-message mechanics exercised locally (download→extract→copy→verify) in a temp
  global-skills sandbox; not written into the live agent skill roots (user's call to actually
  install).

## Boundary

- The zip must live at a reachable URL; the repo cannot publish one from here — the user hosts it
  (GitHub release / any static URL) and substitutes `<host>` in the message. Version stays 1.2.0;
  a release bump can be done in the `VERSION` file before rebuilding.
- Install destination is the current agent's global skills directory (agent-dependent); the
  `$CODEX_HOME`/Codex path remains available via the bundled `scripts/install.py`.
