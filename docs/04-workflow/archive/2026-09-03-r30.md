# R30 - Provider 接入边界 + analysis 权威工件

## 结论

- 新增 `analysis` 权威工件 kind（五类标签），补齐 ANALYSIS 阶段落盘空白；SPECIFICATION
  阶段把它列为必需输入。
- 新增 Provider 边界契约 `docs/provider-boundary.md`：Provider 是隔离、可替换的语义执行器，
  确定性核心零感知，结果永远以 `draft` 落盘、只有显式门禁才能升级为 accepted。
- 实现 `tools/analysis_provider.py`（注册表 + 配置 + `local-fallback`）、
  `tools/analysis_labels.py`（校验/金标准评分）、`tools/analysis.py`（编排、幂等、降级、
  持久化）、`tools/analysis_eval.py`（金标准打分 + 整体 F1 门禁）。
- harness 增补 `analysis_local_fallback` 场景，并把标签校验/评分收敛到 `analysis_labels`
  单一实现，消除重复。

## 验证

- `python tools/behavior_harness.py` -> 7/7 pass。
- CLI 实测：`analysis.py` 落盘 `analysis/build-an-email-login`（draft / local-fallback /
  幂等复用）；`analysis_eval.py` 对金标准打出整体 f1=0.75（选项、决策缺失可见）并可通过
  `--min-f1 0`；`analysis_labels validate` 通过；`py_compile` 全过。
- 未接真实模型；无 Provider 密钥入 git；本轮 `tools/` 无模板/介质同步需求。
