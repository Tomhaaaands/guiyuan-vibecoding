# R14 · manager（2026-08-30）

## 背景

用户拍板核心定位：Web Coding Manager 的核心是 **manage**，脚手架只是空目录分支的默认动作。
目标用户是刚用上豆包 / Workbuddy 的零基础小白——无论他们在 GitHub 上传什么（脚本 / 插件 /
页面 / 完整应用），都要先检测再动手，环境依赖安装前必须提前告知。

## 实现

1. **adopt 接管模式**（bootstrap.py `--mode auto|adopt|scaffold`，auto 按内容自动分支）：
   指纹检测 `manifest.json`→plugin、`package.json` deps→page/app、`pyproject/requirements`→app/script、
   `index.html`→静态页、单文件脚本→script；只补缺失的管理壳（AGENTS/docs 五件套/tools/闸机/
   .gitignore/README/llms.txt），业务代码绝不覆盖；`--force` 也只替换管理文件。
2. **环境预检 + 安装三选一**（`--deps auto|commands|skip`）：先只读体检（git/python/node/uv/gh），
   安装前由 SKILL 引导用户选 自动装 / 只给命令 / 跳过；Python 项目按 `--env` 建 .venv，Node 项目
   跑 `npm install`（auto 时）；`_effective_runtime` 修正 page 等 node 预设不误建 .venv。
3. **新增 artifact 预设** `script` / `plugin` / `page`（profiles/presets/）：页面脚手架自动出
   Next.js 16 骨架；adopt 时按指纹自动选型，避免重复注入 runtime 维度（修复双份约束 bug）。
4. **.env.example 生成**（按类型给占位：DATABASE_URL/SECRET_KEY/API_KEY/PORT 等，.env 已在
   gitignore）；**GitHub 接入** `--github <url>` 设 origin、`--push` 登录后首推。
5. **定位文案重写**：SKILL.md 改为 Web Coding Manager 五阶段（目标→检测→环境告知→执行→
   小白收尾报告）；README/方法论三副本/安装器/vibe-coding-install 副本同步；版本 1.1.0。
