# R20 · public-release hardening and lossless adoption (2026-09-01)

## Scope

Keep install-by-message as the primary entry, retain MIT and version 1.2.0 as the unpublished
release baseline, and explicitly exclude CreatorOS replacement and Flash_assistant migration.

## Implementation

- Existing projects now use read-only `assess` before `adopt`; users choose `keep`, `map`, or
  `managed` for startup, state, ledger, methodology, and tooling independently.
- Assessment hashes block stale application. Confirmed management files are backed up before
  replacement, and `.vibecoding-manager/` stores the baseline and adoption receipts.
- `workflow_optimize.py` proposes at most three receipt-backed candidates, supports explicit
  dismissal, and never applies a workflow change.
- Distribution builds emit `.sha256` and release-manifest companions; forced local Skill updates
  back up the prior copies. `check_package.py` scans tracked source and reachable Git history.

## Verification

- Read-only assessment leaves an existing project unchanged.
- Baseline drift blocks adoption; selected tooling installs the optimization tool; dismissed
  candidates are suppressed on the next review.
- Template and packaged skill copies are synchronized through the normal drift gate.

## Boundary

- No MCP, cloud registry, automatic workflow changes, CreatorOS migration, or Flash_assistant
  migration is introduced in this round.
