# R66 · registry + confirmation anchors (2026-09-05)

## Background

The iteration protocol must survive changes to code layout and template choice. Human-facing
product/technical documents therefore need a derived index, while user decisions at each major
gate need immutable machine evidence.

## Delivered

- scaffold creates `.guiyuan-vibecoding/registry`, `state/tasks`, `anchors`, `receipts`, `indexes`
  and `views` for every new project;
- `project_registry.py` maps module PRD, acceptance, technical specs, project state, roadmap,
  red-lines, changelog and machine receipts/anchors into TOML/JSON derived views;
- `anchor.py` records immutable `REQ`, `PLAN`, `QA` and `RELEASE` confirmations with file hashes;
- generated projects include registry output without changing user-owned source files.

## Verification

- topology scaffold smoke test: web-app + small + rag;
- registry and anchor unit tests;
- full test suite, `check_drift.py`, distribution verification and `git diff --check`.
