# R73 — intent-first intake

## Why

启动阶段曾允许空目录直接按默认 profile 进入脚手架，也只对当前项目需要的 Git/Python/Node/UV/GitHub CLI
做基础预检。这样会把目录指纹误当成产品决策，并且无法让用户在看到模板/目录建议后选择接管方式。

## Change

- `bootstrap.py --mode auto` 在空目录且没有 `--intent` 时只输出产品问题、默认位置和项目名，不写入文件。
- assess JSON 增加项目结构、候选模板及目录、VCM 功能模块目录、产品意图和可选环境盘点字段。
- 人工 assess 摘要隐藏内部匹配分数、风险明细和逐工具诊断，只呈现基础事实与四档接管选择。
- 新增 `--environment-scan` 只读入口，盘点 Agent、共享 Skill 目录、Python/Node 环境、UV 与 GitHub CLI。
- `progressive` 成为渐进接管正式策略，`defer` 保留兼容别名；渐进策略只记录决策，不替换旧管理层。
- 更新公开 Skill、启动契约、方法论、路线图，并通过同步脚本传播到发布载荷。
