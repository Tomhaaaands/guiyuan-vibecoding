2使用流程 Guided Usage · 6 阶段

一次会话完成"管理落地"：先探测目标状态 → 只读评估 → 兼容性决策门 → 环境披露 → 执行 → 验证 → 关闭。项目类型由一句话意图确定性解析，不弹预设菜单；vibe-coding-manager 是 explicit-only，不会自动触发。

Stage 0 · 开场询问项目位置/名称
→
Stage 1 · 状态检测空文件夹 or 已有代码
→
Stage 2 · 兼容门低匹配/相似系统需决策
→
Stage 3 · 环境预检git/python/node/gh 披露
→
Stage 4 · 执行bootstrap.py
→
Stage 5 · 验证check_drift 硬标记=0
→
Stage 6 · 关闭报告 + 里程碑优化

Stage 1 · 空文件夹 → 脚手架

  • 一句话描述 --intent
  • intent-map.toml 确定性解析 profile
  • 高置信直接复述并继续；中/低置信追问 1 个开放问题
  • 默认模块集 web+api+db+worker+tests

Stage 1 · 已有代码 → 只读评估

  • 指纹识别：manifest.json→插件 / package.json→页面/应用 / pyproject→应用/脚本 / index.html→静态页 / 单脚本→脚本
  • 绝不写文件、不装依赖、不动 Git
  • 按工作流选 keep / map / managed

Stage 2 · 兼容性决策门（必须停顿）

  • 低匹配 → full-takeover / takeover / defer / abandon
  • 有相似系统 → keep-map / auto-takeover / abandon
  • 决策前不写任何管理文件；defer/abandon 均不落地

Stage 3 · 环境披露（装前必选）

  • ① Auto-install（推荐）：装 uv + Python/.venv/npm
  • ② Commands only：打印命令由你执行
  • ③ Skip：只加管理层，不安装

Stage 4 · 执行入口

  • --mode auto|assess|adopt|scaffold
  • assess 先出 JSON；adopt 需评估+已确认 workflow
  • Git/GitHub 仅在请求并认证后执行
  • 业务代码永不覆盖

Stage 6 · 里程碑优化

  • workflow_optimize.py 查 receipts
  • ≤3 条有证据的建议捆绑呈现
  • 用户确认才应用，绝不自动/重复已驳回项

3技术实现方案 Modular Monolith · 四平面

先做模块化单体（一处本地运行时 + 仓库权威），Provider 是通道/打包选择而非核心。四平面覆盖认知与执行，manager/ + providers/ 为落地布局。

① Project Brain 项目大脑

维护产品/设计/技术/决策/任务/状态/验证/经验权威产物；上下文编译器按 1,800 token 目标 / 2,500 硬顶输出指针卡与字段切片；续接只发增量 + 内容哈希。

② Planning & Dispatch 规划派发

判定当前阶段、探测缺失决策、拆解里程碑、维护任务依赖、选择下一可执行任务并路由到执行器。

③ Development Operations 研发运营

协调代码/设计/工具执行、构建与测试、Git 变更、部署适配器与结构化 receipts；Codex/Claude/Figma/浏览器/GitHub/托管商均为 Provider 缝后的执行器。

④ Reflection & Evolution 反思进化

把已核验任务结果提炼为红线候选、可复用经验、工作流候选与产品改进提案；策略候选先影子运行再晋升，可版本化可回滚。

模块化单体布局 manager/（10 模块）+ providers/（6 通道）：

manager/ · 核心逻辑

  • intake 意图捕获 / analysis 多维分析
  • artifacts 权威库/一致性 / planning 里程碑任务图
  • context L0-L2 检索与预算 / execution 执行适配与回执
  • verification 构建测试验收门 / reflection 经验红线
  • bridges 外部桥 / evaluation 评估夹具与回归阈值

providers/ · 外部通道（缝）

  • agent 编码智能体 / git / design 设计工具
  • browser 浏览器 / deploy 部署 / memory 记忆
  • 接口先行，MVP 不拆成服务

决策与授权边界

  • 自动：读文件建上下文、草稿产物、授权范围内可逆编辑、本地构建测试、有回执的状态更新
  • 需批准：范围/优先级变更、付费/凭证/外部授权、无回滚的破坏性操作、隐私越界、生产发布

技术硬约束

  • 纯 Python 3.11+，仅标准库（tomllib），UTF-8
  • 无 MCP / 无中央注册表 / 不替代 CreatorOS
  • 路径相对仓库根解析，无硬编码绝对路径
  • 结构变更后重生成 llms.txt

建议扩展 · HTML 本地配置页

  • 随安装包一起分发（assets/），file:// 本地打开，无服务端
  • 读写本地配置：Agent 归属 / 安装目标 / deps 策略 / 同步选项
  • CLI 参数 > HTML 配置 > 默认值 的优先级

建议扩展 · Agent 探测与归属

  • 基于 install_skills --discover 扩展
  • 安装前枚举已装 Agent，询问私有 or 共用
  • 共用需处理更新同步与回滚一致性
12 个确定性工具（均为跨平台纯 Python，覆盖"打包→安装→记录→检索→预算→提炼→门控→同步→优化→安检→索引"）：build_dist · one_click_install · install_skills · rollup_round · hydrate · context_budget · distill · check_drift · sync_copies · workflow_optimize · check_package · gen_llms_txt
